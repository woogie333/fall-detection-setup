# 배터리 모드 전환

진동 노드를 USB 상시 전원에서 **배터리 + 딥슬립**으로 넘기는 절차.

---

## 1. 펌웨어 설정 — 이미 반영되어 있음

`firmware/sensor_node/sensor_node.ino` 상단이 실사용 기준으로 맞춰져 있다.

| 항목 | 값 | 의미 |
|---|---|---|
| `DEBUG_MODE` | **0** | 딥슬립 사용. 1 이면 안 자고 계속 측정만 한다 |
| `USE_BROADCAST` | **0** | 수신기 MAC 으로만 전송 |
| `MONITOR_HZ` | **0** | 실시간 그래프 끔. 자는 동안은 어차피 못 보낸다 |
| `HEARTBEAT_SEC` | **0** | 주기 전송 끔 |
| `HAVE_BATT_SENSE` | **0** | 분압 저항을 달았으면 1 로 (아래 2-1 참고) |
| `BATT_REPORT_SEC` | **3600** | 배터리 잔량 보고 주기(초) |
| `ACT_THRESHOLD` | **3** | 0.19g. 이 이상 흔들려야 깨어난다 |

**되돌리려면** `DEBUG_MODE 1`, `MONITOR_HZ 5` 로 바꾸고 다시 업로드하면
예전처럼 대시보드 실시간 파형을 볼 수 있다.

---

## 2. 깨어난 뒤 순서 — 왜 이렇게 짰는지

낙상 충격은 **20~50ms** 만에 끝난다. 깨어나서 뭘 하든 그보다 오래 걸리면
정작 재야 할 피크를 놓친다. 그래서 이 순서를 지킨다.

```
INT1 상승 → 딥슬립 해제
   ↓  (여기서 아무것도 하지 않는다)
captureImpact()          ← 가장 먼저
   ↓
espnowBegin()            ← WiFi 초기화는 100~200ms 걸린다
   ↓
sendImpact()
   ↓
INT_SOURCE 읽어 래치 해제 → 딥슬립
```

**놓치기 쉬운 것 세 가지**

- `delay(200)` 같은 시리얼 대기를 앞에 두지 말 것
- `adxlBegin()` 재설정을 앞에 두지 말 것 — 딥슬립 중에도 ADXL 은 전원을
  받아 설정을 유지하므로 다시 할 필요가 없다
- `Serial.printf` 도 수 ms 를 먹는다. 측정 후에 찍는다

> ⚠ **그래도 배터리 모드의 peak 값은 USB 모드보다 작게 나온다.**
> 깨어나는 데 걸리는 시간만큼 충격의 앞부분을 놓치기 때문이다.
> **임계값은 반드시 배터리 모드에서 다시 재고 정할 것.** USB 모드에서
> 잡은 값을 그대로 쓰면 실제보다 민감하게 설정된다.

## 2-1. 배터리 잔량 측정 — 저항 2개가 필요하다

**XIAO ESP32C3 에는 배터리 전압 측정 회로가 없다.** Seeed 공식 위키에
"엔지니어가 배터리 전압 측정용으로 할당할 핀이 없었다" 고 명시돼 있다.
직접 분압해야 한다.

```
   BAT+ ──[200kΩ]──┬──[200kΩ]── GND
                   │
                  A0  (D0, GPIO2)
```

배터리 전압의 절반이 A0 로 들어오고, 코드가 2배 해서 복원한다.

**배선 후 펌웨어에서 켤 것:**

```cpp
#define HAVE_BATT_SENSE 1     // 0 이면 잔량이 항상 0 으로 보고된다
```

**보고 시점**

| 언제 | 내용 |
|---|---|
| 충격 발생 시 | 경고와 **함께** 잔량을 실어 보낸다 |
| 1시간마다 | 타이머로 깨어나 잔량만 보고하고 다시 잔다 (`BATT_REPORT_SEC`) |

전압-잔량 변환은 리튬폴리머 방전 곡선을 표로 잡았다. 선형 근사하면
중간 구간에서 20%p 넘게 틀린다.

대시보드 진동센서 카드에 `배터리 60% · 3920mV · 12분 전` 형태로 표시되고,
20% 이하면 빨간색으로 바뀐다.

> **분압 저항도 전류를 먹는다.** 200k+200k = 400kΩ 이면 약 9µA 가
> 상시 흐른다. 딥슬립 전류(약 85µA)의 10% 정도라 감수할 만하지만,
> 수명을 더 늘리려면 저항값을 키우거나(1MΩ 쌍) GPIO 로 분압을
> 껐다 켜는 회로를 넣어야 한다.

## 3. 배터리 연결

**⚠ 극성을 반대로 물리면 XIAO 가 즉시 죽는다.** 연결 전에 반드시 확인한다.

1. 멀티미터 DC 전압 모드로 배터리 두 선의 극성 확인 (양수면 빨간 프로브가 +)
2. 도통 모드로 XIAO 의 BAT− 패드 확인 (GND 핀과 삐 소리가 나는 쪽)
3. 선을 **한 가닥씩** 자르고, 길이를 5mm 이상 어긋나게 (합선 방지)
4. 벗긴 쪽은 작업 전까지 절연 테이프로 덮어둔다
5. 열수축 튜브를 **미리 선에 끼워두고** 납땜한다
6. 인두는 **2~3초 이내**로 짧게. 배터리 셀에서 3~4cm 이상 떨어뜨린다
7. 납땜 후, 전원 넣기 전에 도통으로 극성 재확인

## 4. 전환 후 확인

```bash
# 수신기만 켜두고 노드를 배터리로 돌린 뒤
python3 scripts/impact_test.py -p /dev/ttyACM0
```

- [ ] 노드를 톡 쳤을 때 `IMPACT` 줄이 뜬다
- [ ] `rssi` 가 -70dBm 보다 좋다 (외장 안테나 확인)
- [ ] 가만히 두면 아무것도 안 온다 → 딥슬립 정상
- [ ] **10분 뒤에도** 아무것도 안 온다 → 무한 웨이크 없음

마지막 항목이 중요하다. INT1 이 HIGH 로 고정되면 딥슬립에 들어가자마자
다시 깨어나는 무한 루프가 되어 배터리가 몇 시간 만에 나간다. 조용해야 정상이다.

## 5. 배터리 수명

딥슬립 전류는 XIAO ESP32C3 가 약 44µA(공식 스펙 기준), ADXL345 가
측정 모드에서 약 40µA. 합쳐서 **약 85µA**.

1000mAh 배터리 기준 이론값은 1000 / 0.085 ≈ 11,700시간 = **약 1.4년**이지만,
실제로는 배터리 자가방전, 레귤레이터 손실, 깨어나는 횟수에 따라 훨씬 짧다.
**수 개월**을 현실적인 기대치로 보면 된다.

깨어날 때마다 WiFi 를 켜므로 오탐(문 닫힘, 발소리)이 잦으면 수명이 급격히 준다.
`ACT_THRESHOLD` 를 너무 낮게 잡지 말 것.

> 이 수치는 데이터시트 기반 계산이지 실측이 아니다. 실제 수명은
> 며칠 돌려보고 전압 강하를 재야 알 수 있다.
