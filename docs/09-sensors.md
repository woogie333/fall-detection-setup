# 센서 연결 가이드 — LD2450 · 진동센서 노드

열화상이 붙었으니 나머지 두 센서 차례입니다. **각각 단독으로 검증한 뒤** 융합하세요.
셋을 한꺼번에 붙이면 문제가 생겼을 때 어느 센서 탓인지 알 수 없습니다.

# 1. LD2450 mmWave 레이더

## 1-1. 연결 방법 — 두 가지

### 방법 A: USB-TTL 어댑터 (권장)

CP2102나 CH340 어댑터를 RDK X3 USB에 꽂고, 거기에 LD2450을 연결합니다.

| LD2450 | USB-TTL 어댑터 |
|---|---|
| VCC (5V) | 5V |
| GND | GND |
| TX | **RX** |
| RX | **TX** |

**TX↔RX가 교차**입니다. 같은 이름끼리 연결하면 통신이 안 됩니다. 여기서 제일 많이 틀립니다.

이 방법을 권하는 이유는 **256000 baud 때문**입니다. 비표준 속도라 보드 내장 UART는
지원하지 않을 수 있는데, USB-TTL 칩은 대부분 문제없이 처리합니다.

포트는 `/dev/ttyUSB0`으로 잡힙니다.

### 방법 B: 보드 40핀 GPIO

어댑터 없이 직결합니다. LD2450의 UART 신호는 3.3V라 RDK X3와 레벨이 맞습니다.

| LD2450 | RDK X3 40핀 |
|---|---|
| VCC | 5V (2번 또는 4번 핀) |
| GND | GND (6번 핀) |
| TX | RXD (10번 핀) |
| RX | TXD (8번 핀) |

**전원은 5V, 신호는 3.3V**입니다. 헷갈리지 마세요.

이 방법은 UART가 커널 콘솔로 쓰이고 있으면 먼저 해제해야 하고, 256000을 지원하지
않을 수도 있습니다. **처음이라면 방법 A로 시작하세요.**

## 1-2. 설치 위치

문서 [04-architecture.md](04-architecture.md)의 배치를 따릅니다.

- 벽면 **1.5~2m** 높이, Lepton과 **같은 방향**으로 나란히
- 금속판·전자레인지 근처를 피할 것 (24GHz 반사)
- 케이스에 넣어도 됩니다. 24GHz는 플라스틱을 통과합니다
  (다만 커버 두께는 ABS 기준 **3.92mm** 또는 1mm 미만)

## 1-3. 테스트

```bash
pip install pyserial
sudo usermod -aG dialout $USER      # 권한. 재로그인 필요

cd ~/fall-detection-setup/scripts
python3 ld2450_test.py --list        # 포트 확인
```

**먼저 원시 바이트부터** 확인하세요. 디코딩 문제인지 배선 문제인지 갈립니다.

```bash
python3 ld2450_test.py -p /dev/ttyUSB0 --raw
```

- 데이터가 **전혀 없다** → TX/RX가 바뀌었거나 전원이 없음
- 데이터는 오는데 **헤더(AA FF 03 00)가 없다** → baud가 틀림
- 헤더가 보인다 → 정상

**브라우저 평면도로 확인**합니다. 좌표가 실제와 맞는지 눈으로 보는 게 가장 확실합니다.

```bash
python3 ld2450_test.py -p /dev/ttyUSB0 --web
#  → http://<보드IP>:8091
```

방을 걸어다니면서 점이 따라 움직이는지, 좌우가 뒤집히지 않았는지 보세요.
**좌우가 반대라면 부호 디코딩이 아니라 센서를 뒤집어 단 것**입니다
(디코딩은 검증돼 있습니다).

임계값 보정용 데이터를 모으려면:

```bash
python3 ld2450_test.py -p /dev/ttyUSB0 --csv ld2450_log.csv
```

## 1-4. 알아둘 것

**높이(z)를 측정하지 않습니다.** x는 좌우, y는 거리뿐입니다. "아래로 떨어졌다"를
이 센서 단독으로는 알 수 없어요. 높이 판단은 Lepton이 맡습니다.

**정지한 사람을 놓칩니다.** LD2450은 이름 그대로 *motion* tracking이라, 완전히
멈추면 트랙이 사라지는 경향이 있습니다. 넘어져서 움직이지 않는 상황이 정확히 그거라,
**"넘어진 뒤 계속 누워 있음"의 판단 주체는 Lepton으로 두세요.** 열화상은 사람이
멈춰도 체온이 있는 한 계속 보입니다.

**부호 인코딩이 특이합니다.** 최상위 비트가 1이면 양수입니다. 2의 보수가 아니에요.
`ld2450.py`에 구현돼 있고 검증했으니 직접 파싱하실 일은 없지만, 다른 코드를
참고하실 때 주의하세요.

# 2. 진동센서 노드 (무선)

부품은 [06-purchase-list.md](06-purchase-list.md), 정정 사항은
[07-bom-review.md](07-bom-review.md)를 보세요.

## 2-1. 배선

**센서 노드** (XIAO ESP32C3 + ADXL345)

| ADXL345 (GY-291) | XIAO ESP32C3 | 비고 |
|---|---|---|
| VCC | **3V3** | 5V 아님 |
| GND | GND | |
| SDA | D4 (GPIO6) | |
| SCL | D5 (GPIO7) | |
| INT1 | D1 (GPIO3) | 딥슬립 웨이크업 |
| CS | 3V3 | I2C 모드 고정 |
| SDO | GND | 주소 0x53 |

**VCC를 3V3에 연결하는 이유** — GY-291에 온보드 LDO가 있어 "5V가 정석"이라는 얘기를
보실 수 있지만, **배터리 구동 시 XIAO의 5V 핀은 죽어 있습니다.** USB가 꽂혀야만
살아나요. 배터리로 돌 거라면 3V3이 유일한 선택입니다.

3V3과 GND 핀이 하나씩뿐이라 여러 선을 물려야 하면 미니 브레드보드를 쓰세요.

**배터리** — XIAO 뒷면 `BAT+`(빨강) / `BAT−`(검정) 패드에 납땜.
**극성 반대면 보드가 즉시 죽습니다.** 납땜 전 멀티미터로 확인하고,
납땜 후에는 열수축 튜브로 절연하세요. 리튬 배터리 합선은 발화로 이어집니다.

**수신기** — XIAO를 USB로 RDK X3에 꽂기만 하면 됩니다. 배선도 납땜도 없습니다.

## 2-2. Arduino IDE 준비

파일 → 환경설정 → 추가 보드 관리자 URL에 추가:

```
https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
```

보드 매니저에서 **esp32** 설치 → 보드 선택 **XIAO_ESP32C3**

## 2-3. 순서 — 이 순서를 지키세요

### ① 수신기 먼저

`firmware/receiver/receiver.ino`를 XIAO 하나에 업로드합니다.

시리얼 모니터(115200)에 이렇게 찍힙니다.

```
# 내 MAC: 34:85:18:XX:XX:XX
```

**이 MAC 주소를 복사하세요.** 다음 단계에서 씁니다.

### ② 센서 노드 — 먼저 DEBUG_MODE 로

`firmware/sensor_node/sensor_node.ino`를 열고 두 곳을 고칩니다.

```cpp
#define DEBUG_MODE 1        // 그대로 둡니다
uint8_t RECEIVER_MAC[6] = { 0x34, 0x85, 0x18, 0xXX, 0xXX, 0xXX };  // ① 에서 복사한 값
```

두 번째 XIAO에 업로드하고 시리얼 모니터를 보세요.

```
x= +0.02 y= -0.01 z= +1.00  |mag|= 1.00g  INT1=0
```

정지 상태에서 z축이 약 1.00g면 정상입니다(중력).

**바닥을 두드리거나 물건을 떨어뜨려 보세요.** `|mag|` 값이 얼마나 튀는지 기록해두세요.
이 값으로 임계값을 정합니다.

### ③ 임계값 조정

기본값 `ACT_THRESHOLD = 32`는 약 2.0g입니다(62.5 mg/LSB).

- 발소리에도 반응하면 → 값을 **올리세요**
- 실제 충격을 못 잡으면 → **내리세요**

너무 낮으면 계속 깨어나 배터리를 갉아먹습니다.

### ④ 수신 확인

RDK X3에 수신기를 꽂고:

```bash
cd ~/fall-detection-setup/scripts
python3 impact_test.py --raw       # MAC 확인 및 연결 점검
python3 impact_test.py             # 충격 이벤트 표시
```

DEBUG_MODE에서는 2초에 한 번까지 전송하므로, 바닥을 두드리면 보드 쪽에 뜹니다.

```
[14:23:11] vib-01 #3  peak= 3.21g  dur=  85ms  rssi=-48dBm  ████████████
```

### ⑤ 마지막에 딥슬립

로직이 다 검증된 뒤에 `DEBUG_MODE`를 `0`으로 바꿔 다시 업로드합니다.
**이걸 먼저 하면 시리얼 디버깅이 거의 불가능해집니다.**

### ⑥ 배터리 전환

USB를 빼고 배터리로 동작하는지 확인합니다. 소비전류는 멀티미터로 재보세요.
딥슬립에서 100µA 안팎이면 정상이고, 밀리암페어 단위면 딥슬립에 못 들어간 겁니다.

## 2-4. 설치

바닥 구조에 **단단히 결합**되어야 합니다. 벽에 붙이면 진동이 감쇠돼서 못 잡습니다.

양면테이프로 **넓게** 접착하세요. 고무발이나 스탠드오프를 넣으면 진동이 사라져
센서가 무의미해집니다.

# 4. 문제 해결

| 증상 | 원인과 대응 |
|---|---|
| LD2450 데이터 없음 | TX/RX 교차 확인. 전원 5V 확인 |
| 헤더는 없고 바이트만 옴 | baud 불일치. 256000 확인 |
| `Permission denied` (시리얼) | `sudo usermod -aG dialout $USER` 후 재로그인 |
| 좌표 좌우 반전 | 센서를 뒤집어 단 것. 물리적으로 돌리세요 |
| 정지한 사람이 사라짐 | LD2450의 정상 특성. Lepton으로 보완 |
| ADXL345 `DEVID` 불일치 | 배선 확인. SDO는 GND, CS는 3V3 |
| ESP-NOW 전송 실패 | RECEIVER_MAC 확인. 두 보드가 같은 채널인지 |
| 딥슬립에서 안 깨어남 | INT1이 GPIO0~5 범위 핀에 연결됐는지 |
| 배터리 소모가 빠름 | 딥슬립 미진입 또는 임계값이 너무 낮음 |
| 수신기 포트 없음 | `ls /dev/ttyACM*`, `dmesg \| tail` |

## 진동 전달 실측 (2026-08, 마루 바닥)

| 측정 | 값 |
|---|---|
| 정지 시 잡음 peak (이동평균 후) | 약 0.04 g |
| 주먹 타격, 0.1 m | 0.90 g |
| 주먹 타격, 2.5 m | 0.16 g |
| 2.6 kg 가방 1 m 낙하, 1.5 m | 1.50 g |

두 타격 점으로 감쇠 지수를 구하면 **A ∝ r^-0.54**. 판 위 표면파의
원통형 확산(r^-0.5)과 거의 일치하므로 물리적으로 타당한 값이다.

이 곡선을 가방 측정에 적용한 예측:

| 거리 | 예상 |
|---|---|
| 2 m | 1.29 g |
| 3 m | 1.03 g |
| 4 m | 0.89 g |
| 5 m | 0.79 g |

**결론: 마루에서는 노드 하나로 방 하나를 커버할 수 있다.**

한계 — 점이 두 개뿐이고 0.1 m 는 근거리(표면파가 퍼지기 전)라 곡선이
확정적이지 않다. 가방으로 3 m 를 한 번 재면 검증된다. 카펫·매트 위나
문턱 너머는 별도 측정이 필요하다.

현재 기본값은 `--escalate-g 0.8`. 계산상 5 m 예상값(0.79g)과 거의 같으므로
방 끝의 낙상은 승격되지 않을 수 있다. **통합 테스트에서 실제 낙상 값을 재고
확정할 것.** 놓치는 사례가 나오면 0.6 으로 내린다.
