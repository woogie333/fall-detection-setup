# 1. 원격접속 환경 정리

## 1-1. 고정 IP (먼저 해야 함)

IP가 바뀌면 VS Code, VNC, SmartThings 앱 설정이 전부 어긋납니다. 이것부터 잡으세요.

```bash
nmcli con show                       # 프로필 이름 확인 (DEVICE가 wlan0인 행)
ip route | grep default              # 현재 게이트웨이 확인

sudo nmcli con mod "프로필이름" \
  ipv4.addresses 192.168.0.100/24 \
  ipv4.gateway 192.168.0.1 \
  ipv4.dns "8.8.8.8,1.1.1.1" \
  ipv4.method manual

sudo nmcli con down "프로필이름" && sudo nmcli con up "프로필이름"
```

**더 나은 방법**: 공유기 관리 페이지에서 보드 MAC에 **DHCP 예약**을 거세요.
보드 설정을 안 건드리니 실패해도 복구가 쉽고, WiFi 재접속 시 프로필이 꼬이는 문제도 없습니다.

## 1-2. VS Code Remote-SSH (주력 편집 환경)

일상 작업은 이걸로 하세요. VNC보다 훨씬 빠르고 안정적입니다.

**PC에서만** 하면 됩니다. 보드에 설치할 건 없어요.

1. VS Code → 확장 → `Remote - SSH` 설치
2. `Ctrl+Shift+P` → `Remote-SSH: Connect to Host` → `sunrise@192.168.0.100`
3. 처음 접속 시 서버 컴포넌트가 자동 설치됩니다 (arm64 자동 인식, 1~2분)

**비밀번호 없이 접속하기** (권장 — 매번 입력이 번거롭습니다)

```bash
# PC에서
ssh-keygen -t ed25519          # 이미 있으면 건너뜀
ssh-copy-id sunrise@192.168.0.100
```

**호스트 등록** — PC의 `~/.ssh/config`에 추가하면 이름으로 접속됩니다.

```
Host rdk
    HostName 192.168.0.100
    User sunrise
    ServerAliveInterval 30
    ServerAliveCountMax 6
```

`ServerAliveInterval`을 넣어두면 WiFi가 잠깐 끊겨도 세션이 바로 죽지 않습니다.
이후 `ssh rdk` 또는 VS Code에서 `rdk`만 선택하면 됩니다.

## 1-3. VNC (GUI가 꼭 필요할 때만)

```bash
sudo apt install -y tigervnc-standalone-server dbus-x11 xfce4 xfce4-goodies
```

`~/.vnc/xstartup`:

```bash
#!/bin/sh
unset SESSION_MANAGER
unset DBUS_SESSION_BUS_ADDRESS
exec dbus-launch --exit-with-session startxfce4
```

```bash
chmod +x ~/.vnc/xstartup
vncpasswd                        # 비밀번호 설정 (8자 제한)
```

자동 시작 등록:

```bash
sudo tee /etc/systemd/system/vncserver@.service > /dev/null <<EOF
[Unit]
Description=TigerVNC server on display %i
After=network.target

[Service]
Type=forking
User=$USER
WorkingDirectory=$HOME
PIDFile=$HOME/.vnc/%H:%i.pid
ExecStartPre=-/usr/bin/vncserver -kill :%i
ExecStart=/usr/bin/vncserver :%i -localhost no -geometry 1280x800 -depth 24
ExecStop=/usr/bin/vncserver -kill :%i
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now vncserver@1
```

접속: TigerVNC Viewer에서 `192.168.0.100:1`

`ls ~/.vnc/*.pid`로 실제 PID 파일명을 확인하고 유닛의 `PIDFile` 경로를 맞추세요.
호스트명 형식이 환경마다 다릅니다.

## 1-4. 카메라·영상 확인은 브라우저로

VNC로 영상을 보는 건 느리고 불안정합니다. `camera_test.py --stream`을 쓰면
폰이나 PC 브라우저에서 `http://192.168.0.100:8090`으로 바로 보입니다.
열화상 확인도 `--raw` 옵션으로 같은 경로를 씁니다.

## 1-5. 정리

| 용도 | 도구 |
|---|---|
| 코드 편집·실행 (일상) | **VS Code Remote-SSH** |
| 영상 확인 | **브라우저 스트리밍** (`camera_test.py --stream`) |
| GUI 앱이 꼭 필요할 때 | VNC |
| 빠른 명령 | `ssh rdk` |

# 3. 무선 진동센서 — 전체 부품 목록

## 3-1. 구성 개요

```
  [ 바닥 센서 노드 ]                      [ 메인 보드 ]

  ADXL345 ──I2C── XIAO ESP32C3            RDK X3
                       │                     │
                  리튬 배터리            XIAO ESP32C3 (수신기)
                                              │ USB
                       └───── ESP-NOW ────────┘
                            (2.4GHz 직접 통신)
```

**설계 요점 세 가지**

ESP-NOW를 쓰는 이유는 공유기를 거치지 않아 지연이 2~5ms로 짧고, 공유기가 죽어도
동작하며, WiFi 재접속 대기가 없어 배터리에 유리하기 때문입니다.

RDK X3는 ESP-NOW를 직접 못 받으므로 **수신용 ESP32를 USB로 꽂습니다.**
보드에서는 `/dev/ttyACM0` 시리얼로 읽으면 됩니다.

XIAO ESP32C3를 고른 이유는 **배터리 충전 회로가 내장**되어 있어서입니다.
TP4056 같은 별도 충전 모듈이 필요 없어 부품과 배선이 줄어듭니다.

|---|---|---|---|---|
| 1 | Seeed XIAO ESP32C3 | **2** | 6,000원 | 센서 노드용 1 + 수신기용 1 |
| 2 | ADXL345 브레이크아웃 (GY-291) | 1 | 3,000원 | SW-420 대체 |
| 3 | 리튬폴리머 배터리 3.7V 1000mAh (503450) | 1 | 6,000원 | **JST PH 2.0 커넥터 달린 것** |
| 4 | USB-C 케이블 (데이터 지원) | 2 | 3,000원 | 수신기 연결 + 노드 충전·개발용 |

| 열수축 튜브 | 배선 절연 |

## 3-4. 필요 없는 것 (혼동 방지)

이런 걸 사라는 글을 보실 수 있는데, 이 구성에서는 **불필요**합니다.

- **TP4056 충전 모듈** — XIAO에 내장되어 있음
- **18650 배터리 + 홀더** — 리튬폴리머가 얇고 가벼워 바닥 설치에 유리
- **레벨 시프터** — XIAO와 ADXL345 모두 3.3V, 직결 가능
- **외부 안테나** — 실내 수 미터 거리엔 온보드 안테나로 충분
- **풀업 저항** — GY-291 브레이크아웃에 내장

## 3-5. 배선

**센서 노드**

| ADXL345 | XIAO ESP32C3 | 비고 |
|---|---|---|
| VCC | 3V3 | 5V 아님 |
| GND | GND | |
| SDA | D4 (GPIO6) | I2C 데이터 |
| SCL | D5 (GPIO7) | I2C 클럭 |
| INT1 | D1 (GPIO3) | **딥슬립 웨이크업용. 반드시 연결** |
| CS | 3V3 | I2C 모드 고정 |
| SDO | GND | I2C 주소를 0x53으로 |

배터리는 XIAO 뒷면의 **BAT+ / BAT−** 패드에 납땜합니다. 극성을 반대로 하면
보드가 즉시 망가지니 배터리 선 색(빨강=+, 검정=−)을 두 번 확인하세요.

**수신기**: XIAO를 USB 케이블로 RDK X3에 꽂기만 하면 끝입니다.

```bash
ls /dev/ttyACM*        # 인식 확인
```

## 3-6. 전력 계산

| 상태 | 소비 전류 | 비중 |
|---|---|---|
| XIAO 딥슬립 | 약 43 µA | 대부분의 시간 |
| ADXL345 대기(인터럽트 감시) | 약 40 µA | 항상 |
| XIAO 활성 + 송신 | 약 74 mA | 충격 시 0.5초 정도 |

평상시 합계 약 83 µA. 1000mAh 배터리로 산술상 1년 이상이지만, 자가방전과
간헐적 웨이크업을 감안하면 **실사용 3~6개월**로 보시면 됩니다.

**이 수치는 딥슬립을 제대로 구현했을 때의 얘기입니다.** 그냥 루프 돌면서
계속 측정하면 하루도 못 갑니다. ADXL345의 Activity 인터럽트로 ESP32를 깨우는
구조가 반드시 필요합니다.

## 3-7. 검증 순서

1. XIAO 2개에 각각 블링크 예제 올려서 동작 확인
2. 노드에서 ADXL345 I2C 읽기 → 시리얼로 가속도 출력
3. ESP-NOW 송수신 테스트 (충격값 전달)
4. RDK X3에서 `/dev/ttyACM0` 읽기
5. 딥슬립 + 인터럽트 웨이크업 구현
6. 배터리로 전환, 소비전류 측정

**5번을 마지막에 하세요.** 딥슬립 상태에서는 시리얼 디버깅이 어려워서,
먼저 유선·상시전원으로 로직을 완성한 뒤 절전을 얹는 게 훨씬 빠릅니다.

# 4. 3D 모델링 제원

## 4-1. 가장 중요한 제약 — 열화상은 플라스틱을 못 뚫습니다

**Lepton 앞에는 반드시 뚫린 구멍이 있어야 합니다.**

장파장 적외선(LWIR, 8~14 µm)은 일반 플라스틱, 아크릴, 유리를 **완전히 차단**합니다.
얇은 필름도 안 됩니다. 투과창을 쓰려면 게르마늄 렌즈가 필요한데 수십만 원대라
현실적이지 않습니다.

따라서 케이스 전면에 **렌즈 지름보다 약간 큰 개구부**를 내고, 렌즈가 그 구멍에
맞닿거나 살짝 튀어나오게 설계하세요. 화각(HFOV 56°)이 개구부 가장자리에
가리지 않도록 구멍 벽을 바깥쪽으로 벌리는(카운터싱크) 형태가 좋습니다.

이걸 모르고 투명 커버를 씌우면 **아무것도 안 보입니다.** 조립 후 발견하면
케이스를 다시 뽑아야 해요.

## 4-2. 반대로 LD2450은 덮어야 합니다

24GHz 전파는 플라스틱을 통과하므로 **레이더는 케이스 안에 숨기는 것이 정상**입니다.
다만 두 가지 규칙이 있습니다.

커버 두께를 **반파장의 정수배**로 맞추면 반사 손실이 줄어듭니다. ABS(비유전율 2.5)
기준 약 **3.92 mm**입니다. 어렵다면 아주 얇게(1mm 미만) 만드는 것도 방법입니다.
어중간한 두께(2mm 내외)가 가장 나쁩니다.

레이더 **전면에는 금속이 없어야** 합니다. 나사, 도전성 도료, 금속 필러가 섞인
필라멘트 모두 안 됩니다. 뒤쪽 금속 차폐는 오히려 후방 로브를 줄여줍니다.

## 4-5. 전원·발열

RDK X3는 **USB Type-C로 5V 3A**를 받습니다. 케이스 측면에 Type-C 커넥터
접근구를 내야 하고, 5V 3A를 안정적으로 주는 어댑터를 쓰세요. 전력이 모자라면
카메라 캡처 중에 리부팅이 걸립니다.

방열은 벤더 요구사항이 명시돼 있지 않지만, 열화상 캡처와 추론을 상시 돌리면
발열이 상당합니다. **방열판 부착 공간과 통풍구를 넣어두세요.** 다만 통풍구가
Lepton 개구부와 가까우면 케이스 내부 열이 화면에 잡힐 수 있으니 떨어뜨리세요.

## 4-6. 형태 제안

첨부한 HTML 스케치를 브라우저에서 열어보세요. 두 케이스의 배치안과
치수를 그림으로 정리했습니다.

**메인 유닛** — 벽걸이 세로형

RDK X3를 바닥에 눕히고, 그 앞쪽에 PureThermal과 LD2450을 위아래로
배치하는 구조입니다. 전면 패널에 Lepton 개구부(뚫림)와 레이더 영역(덮개)이
같이 있습니다. 벽면 브래킷은 각도 조절이 되면 좋습니다 — 설치 높이에 따라
아래로 10~20° 기울여야 바닥이 화각에 들어옵니다.

**센서 노드** — 바닥 밀착 납작형

높이를 최대한 낮춰야 발에 걸리지 않습니다. 배터리가 가장 두꺼우니(5mm)
전체 두께는 12~15mm 정도로 잡으세요. **바닥면은 평평하게** 해서 양면테이프로
넓게 접착해야 진동이 잘 전달됩니다. 고무발이나 스탠드오프를 넣으면
진동이 감쇠되어 센서가 무의미해집니다.

ADXL345는 케이스 바닥면에 **단단히 고정**하세요. 공중에 뜨거나 스펀지 위에
있으면 충격을 못 잡습니다.
